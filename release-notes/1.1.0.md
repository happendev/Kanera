A board no longer has to live in a workspace. A standalone board has its own lists, labels, custom fields, checklist templates, automations, members and settings, so you can start with one project, client or personal workflow and add a workspace later, when several boards should share one setup.

This release also adds board syncing, access set board by board, two-factor sign-in, checklist items with their own details, and sign-in with OAuth for AI agents.

## Start with a single board

When you set up Kanera for the first time, choose **Create a board** or **Create a workspace**. Later, use **New standalone board** in the sidebar to add another.

Open **Board settings** on a standalone board to manage its lists, fields, labels, automations, guests and API keys without affecting any other board. Under **General**, give it a **Board group** to keep related standalone boards together in the sidebar.

## Sync cards from one board to another

A board mirror sends cards from selected lists on one board to another board, for example from a client's **Bugs** list into your team's development queue. Open the board menu and choose **Mirror this board**, pick the target board, then choose the source lists and where their cards should arrive.

The source stays in charge of the shared content: title, description, labels, custom fields, comments, attachments and checklists follow it. The target team keeps its own assignees and due dates. Turn on **Enable board linking** in the **General** settings of both workspaces or standalone boards first.

## Control who sees what

Access is now set per board. In **Workspace settings → Boards**, select **Manage access** on a board to give each person **Editor** or **Observer** access. Turn on **Assigned items only** to show someone only the cards assigned to them, directly or through a checklist item. Guests use the same roles.

Protect your account with two-factor authentication. In **Settings → Profile**, select **Set up authenticator**, scan the QR code and keep the recovery codes somewhere safe. Organisation admins can require two-factor authentication for everyone.

## New features

- [Boards] Standalone boards with their own lists, fields, labels, automations and members
- [Boards] Board mirrors copy cards from selected lists to another board and keep them updated
- [Members] Editor or Observer access per board, with an optional Assigned items only restriction
- [Security] Two-factor sign-in with an authenticator app and single-use recovery codes
- [Cards] Open a checklist item to add a description and sub-checklists
- [Cards] Edit custom field values on many selected cards at once
- [Cards] **Copy to board…** now reaches boards in other workspaces
- [Notifications] Search notifications and group them by day, board or user
- [Reporting] List view adds **Break down by**, overall totals and custom-field filters
- [API] Personal API keys that act as you, under **Settings → API Keys**
- [MCP] AI clients can connect by signing in with OAuth instead of using an API key

## Improvements

- [Boards] **Select all cards** in a list's menu, or select a whole group in List view
- [Boards] Deleting a list or board first tells you how many cards will be deleted
- [Onboarding] New Project Delivery and blank templates; templates can add automations and checklist templates
- [Import] Connect Trello during import to copy uploaded attachments instead of only linking them
- [Cards] Videos play in the attachment viewer, and leaving unsaved text asks you to confirm
- [Mobile] Lists snap into place as you swipe, and the sidebar expands with a swipe
- [MCP] Bulk card actions, paged card lists, sub-checklists and a documentation search tool

## Bug fixes

- [Mobile] Dragging cards on phones and scrolling in Safari work reliably
- [Notifications] Opening a card marks its notifications read, and badges count each card once
- [Offline] Live updates reconnect after the app returns from the background

## Self-hosting

- Set `MFA_ENCRYPTION_KEY` to a random value of at least 32 characters before upgrading. Keep it stable: changing it invalidates every enrolled authenticator.
- In production, `SECRETS_ENCRYPTION_KEY` is now required and must differ from `JWT_SECRET`.
- Docker Compose now requires `POSTGRES_PASSWORD` in `.env`. On an existing database, set it to the current password; the previous Compose file used `kanera`.
- For OAuth sign-in from remote AI clients, set `PUBLIC_API_OAUTH_ISSUER` and `MCP_PUBLIC_URL`, and route the OAuth paths described in `DEPLOY.md`.
