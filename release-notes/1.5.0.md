Kanera now has a command-line tool and a TypeScript SDK. Install the CLI with `npm install --global @kanera/cli` (Node 22 or newer), sign in with `kanera auth login`, and run commands such as `kanera work`, `kanera card MKT-42` or `kanera card done MKT-42`.

`kanera commands --json` lists everything the CLI can do, so AI agents that can run shell commands can use it too. `kanera setup claude` adds the Kanera skill to Claude Code.

The SDK, `@kanera/sdk`, wraps the public API for Node, Bun, Deno, Cloudflare Workers and browsers. It accepts a card key such as `MKT-42` wherever a card is expected, pages through results for you and verifies webhook signatures.

## Give agents read-only API keys

When you create a personal key in **Profile settings → API keys**, choose **Write** or **Read only**. A read-only key can read everything you can access but cannot change content, manage keys or change account settings, which makes it the right key for an AI agent that should only look.

A key's scope cannot be changed after it is created. Personal keys you created before this release keep read and write access.

## See which boards need attention

Select the radar button on a board to open **Board overview**. It counts active, overdue, unassigned and inactive cards, shows what is due in the next 7 days and how many cards each list holds. Select a count to filter the board to those cards. The button itself shows whether the board is on track, needs attention or is at risk.

A card with no activity for 14 days is marked inactive. Change the period, or choose which signals count towards board health, under **Workspace settings → General**. Portfolio also shows each board's work risk.

## New features

- [CLI] The `kanera` command-line tool for cards, comments and Up next from a terminal
- [SDK] `@kanera/sdk`, a TypeScript client for the public API
- [API] Personal API keys can be created as read-only
- [Boards] Board overview with active, overdue, unassigned, inactive and due-soon counts
- [Boards] Cards without recent activity are marked inactive, after 14 days by default
- [Settings] Choose the inactivity period and the signals that count towards board health
- [Reporting] Portfolio shows each board's work risk
- [Automations] **Examples** adds ready-made rules matched to your lists and labels, switched off
- [Notifications] Optionally get device notifications for boards and cards you watch
- [Comments] Workspace admins can delete other people's comments on their boards

## Self-hosting

- Set `MCP_SERVER_PUBLIC_URL` in `.env` to your public MCP endpoint before upgrading; Docker Compose now refuses to start without it.
- If you expose MCP, route `/.well-known/oauth-protected-resource/mcp` to the `mcp` service as well as `/mcp` and `/.well-known/oauth-protected-resource`.
- Postgres, Valkey and the monitoring images are now pinned to exact versions. The usual upgrade command leaves them running; run `docker compose up -d postgres valkey` to move to the pinned versions.
- New optional MCP settings: `MCP_UPSTREAM_TIMEOUT_MS` (default `15000`) and `MCP_TOOL_OUTPUT_MAX_BYTES` (default `1048576`).
